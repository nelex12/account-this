# AccountThis

AccountThis помогает компании учитывать инструменты и отслеживать, у кого они находятся. При выдаче или возврате сотрудник сканирует наклейку инструмента и показывает завхозу QR-код операции. Завхоз может проверить подпись и сохранить запись без интернета. Когда связь появляется, приложение отправляет накопленные операции на сервер. Владелец управляет реестром и сотрудниками, просматривает журнал и получает уведомления о записях, требующих проверки.

## Стек

Клиент написан на React и TypeScript, для сборки используется Vite. Серверная часть работает на C# и ASP.NET Core 8. Данные хранятся в PostgreSQL 16, доступ к базе идёт через Npgsql. RabbitMQ 4 передаёт события фоновому обработчику. Сервисы запускаются через Docker Compose. Nginx обслуживает приложение, а на сервере Caddy обеспечивает HTTPS.

## Структура репозитория

- `frontend/` — веб-приложение.
- `backend/AccountThis.Api/` — HTTP API, бизнес-логика и SQL-миграции.
- `backend/AccountThis.Worker/` — обработчики аудита и уведомлений.
- `backend/AccountThis.Shared/` — контракты событий, настройки очередей и конфигурация.
- `backend/AccountThis.Api.Tests/`, `e2e/`, `loadtest/` — тесты серверной части, сквозные сценарии Playwright и нагрузочные тесты k6.
- `api.yaml` — спецификация HTTP API. В `docs/` лежат схемы архитектуры, описание событий и результаты нагрузочных тестов.
- `docker-compose.yml` — локальное окружение. Для развёртывания на сервере используются также `docker-compose.prod.yml` и `deploy/`.

## Архитектура системы

Nginx раздаёт клиент и передаёт запросы `/api/` в ASP.NET Core. При синхронизации API проверяет подписи и время операций, сохраняет их в журнале PostgreSQL и возвращает результат для каждой записи. Повторная отправка после обрыва связи не дублирует запись.

API записывает изменение и событие в таблицу `outbox_events` в одной транзакции. Фоновая служба API публикует событие в RabbitMQ и удаляет его из таблицы после подтверждения брокера. Worker читает две очереди. Из одной он записывает события в журнал аудита, из другой создаёт уведомления владельцу. Подробнее — в [описании событий](docs/events.md) и на [схемах архитектуры](docs/architecture/README.md).

## Быстрый старт

Для локального запуска в Windows нужны Docker Desktop с запущенным движком и Node.js для генерации ключей. Выполняйте команды в PowerShell из корня репозитория.

1. При первом запуске создайте файл настроек командой `Copy-Item env.example .env`.
2. Задайте в `.env` пароли PostgreSQL и RabbitMQ. Выполните `.\generate-keys.bat` и перенесите выведенные значения `SERVER_SIGNING_KEY` и `JWT_SIGNING_KEY` в одноимённые поля. Сохраните ключи для следующих запусков.
3. Запустите `docker compose up -d --build`. При старте API применит миграции базы.
4. Откройте [приложение](http://localhost) и зарегистрируйте владельца компании. При `ENABLE_SWAGGER=true` доступен [Swagger UI](http://localhost:5000/swagger).

Остановить сервисы с сохранением данных можно командой `docker compose down`. Для запуска тестов серверной части при работающем Docker выполните `dotnet test backend/AccountThis.Api/AccountThis.Api.slnx`.
