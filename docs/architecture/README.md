# Архитектура AccountThis

Четыре схемы от общей к подробной — по уровням модели C4. Исходники — Mermaid (`*.mmd`),
картинки — в [images/](images): PNG шириной 4K (3840 px), большие схемы — ещё и в 8K (7680 px) для крупного просмотра.

## Обозначения

- Зелёный овал — пользователь (роль); синий — middleware и фронтенд; тёмно-серый — код backend
  (контроллеры, сервисы); фиолетовый цилиндр — хранилище; коричневый — инфраструктура и файлы настроек.
- Сплошная стрелка — вызов; пунктир — данные вне HTTP-запроса (оффлайн-QR, настройки из `.env`, FK и view в БД).

## Схемы и код

Схемы описывают, **как система должна работать** по `api.yaml`, `database/init.sql` и документу
«Описание проекта подробно…». Сейчас в коде:

- сервисы и Security — заглушки (`NotImplementedException`), контроллеры уже вызывают сервисы;
- middleware проверки JWT не подключено: в `Program.cs` нет `AddAuthentication` / `UseAuthentication` / `UseAuthorization`.

Строка QR сотрудника разбирается дважды: фронтендом завхоза при оффлайн-проверке и сервером в `/api/sync`
(`QrPayloadParser`). Серверу нужны поля из QR для записи в `rental_logs`, а флаги проверки выставляет только он —
данным с устройства завхоза сервер не доверяет.

Изоляция компаний: `company_id` пользователя лежит в JWT (claim `company_id`), контроллеры передают его в сервисы,
а сервисы добавляют в каждый запрос к `users`, `tools` и журналу. Чужой объект неотличим от несуществующего (404),
а в `/api/sync` чужие сотрудник и инструмент получают флаги `UNKNOWN_WORKER` и `UNKNOWN_TOOL`. Таблицы `users`, `tools`
и `rental_logs` ссылаются на `companies`; у журнала свой `company_id` (компания завхоза), а составные внешние ключи
`(issuer_id, company_id)`, `(worker_id, company_id)`, `(tool_id, company_id)` не дают записать в журнал
ссылку на другую компанию даже при ошибке в коде.

id пользователей, компаний и инструментов — UUID. Они не перебираются и не раскрывают масштаб, но защитой доступа не являются:
её дают проверки компании. id записей журнала — обычные числа: на вход они нигде не принимаются.
Списка компаний нет: Owner берёт id своей компании в `GET /api/companies/my` и сообщает его сотрудникам и завхозам.

## Как изменить схему

1. Поправьте нужный `*.mmd`. Смотреть результат удобно на [mermaid.live](https://mermaid.live)
   или в VS Code с расширением Markdown Preview Mermaid Support.
2. Запустите `render.bat` (или `node render.mjs`) — картинки в `images/` перерисуются (нужен Node.js).
   Ширина картинок задаётся в `render.mjs`, отступы и плотность — в блоке `config` в начале каждого `*.mmd`.
