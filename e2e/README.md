# E2E-тесты (Playwright)

Сквозные тесты в настоящем браузере (Chromium) против **локального** стека из `docker-compose.yml`.
Продакшен не используется. Каждый прогон создаёт свою компанию и пользователей со случайными паролями
(после прогона они лежат в `e2e/.run/last-run.json`, чтобы можно было зайти и посмотреть руками).

## Запуск

```
docker compose up -d --build          # в корне репозитория; чистая база: docker compose down -v
cd e2e
npm install
npx playwright install chromium       # один раз
npx playwright test                   # ~1 минута
npx playwright show-report            # HTML-отчёт: шаги, скриншоты и trace упавших тестов
```

Другой адрес (например, Vite): `E2E_BASE_URL=http://localhost:5173 npx playwright test`.

## Как устроено

- `tests/main-flow.spec.ts` — сценарии по порядку (они зависят друг от друга: Owner → заявки → инструменты → выдача → возврат...).
- У каждого человека свой браузерный контекст (отдельные cookie, IndexedDB и ключи, как у разных телефонов).
  Owner — экран компьютера, Issuer и Worker — экран телефона.
- `helpers/fakeCamera.ts` — виртуальная камера: подменяет `getUserMedia` потоком из `<canvas>`, в который тест кладёт
  картинку. Сотруднику «показывают» PNG-наклейку, скачанную у владельца, а завхозу — скриншот QR с экрана сотрудника.
  Распознавание QR (zxing-wasm) и все проверки подписей в приложении работают по-настоящему.
- Работа без сети — `context.setOffline(true)`; просроченный QR — управляемые часы `page.clock`.
